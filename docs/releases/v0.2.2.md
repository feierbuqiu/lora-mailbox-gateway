# LoRa Mailbox Gateway v0.2.2

Version 0.2.2 fixes contradictory battery readings and premature low-battery email caused by two independent telemetry paths. It is a remote-only correction for an already-installed mailbox node: no node retrieval and no firmware reflash are required.

## Highlights

- Split raw gateway telemetry from cloud-calibrated telemetry into separately owned retained MQTT topics.
- Added `mailbox/heartbeat-calibrated` and `mailbox/status-calibrated` as the stable panel battery source.
- Kept `mailbox/heartbeat` and `mailbox/status` gateway-owned, eliminating the overwrite race that made the panel alternate between raw and calibrated voltage.
- Updated the panel to prefer calibrated voltage, percentage, and alert state while continuing to use raw topics for current mailbox state.
- Added an explicit battery-source label with calibration offset and filter sample count.
- Added a one-time migration path for calibrated retained payloads created by v0.2.1.
- Repaired the live Make scenario filter so uncalibrated legacy firmware subjects no longer generate premature low/critical battery mail; delivery and calibrated alerts remain enabled.
- Preserved the existing deployment calibration, five-sample median, 10 mV display step, and linear `3.3 V = 0%`, `4.2 V = 100%` mapping.
- Confirmed from the firmware call path that a low-battery classification only updates alert state and sends a webhook. It does not shut down, power off, or deep-sleep the installed node.

## Root Cause and Resolution

The installed firmware reports the divider/ADC result without the deployment-specific correction. The cloud monitor adds the measured offset and recomputes percentage correctly. Version 0.2.1 wrote that corrected payload back to the same retained topics owned by the home gateway. Each five-minute gateway heartbeat temporarily replaced the calibrated value with the raw value, and the next one-minute Worker run replaced it again. The panel therefore appeared to jump between two contradictory readings.

Version 0.2.2 makes topic ownership explicit: the gateway writes raw topics, the Worker writes calibrated topics, and the panel chooses calibrated fields. A new raw heartbeat can no longer erase the last trustworthy calibrated display value while the Worker processes the next sample.

The two observed premature messages were emitted by the legacy firmware webhook path using raw percentage. The live Make filter had retained its label but lost its condition, so those subjects still reached Gmail. The condition is now restored with two explicit AND rules that reject subjects containing `Mailbox: battery low` or `Mailbox: battery critical`. The separate `Mailbox: battery telemetry invalid` and `Mailbox: calibrated battery ...` subjects remain deliverable.

## Live Validation

- MQTT before correction: the node path reported approximately `3594 mV / 19%` while the cloud path corrected the same sample to approximately `3760 mV / 51%`.
- MQTT after deployment: dedicated calibrated heartbeat/status topics retained `3760 mV / 51%`, `battery_alert=ok`, the `+164 mV` deployment offset, and five filter samples.
- The authenticated production panel then showed `Connected`, `3.75 V / 50%`, `Cloud calibrated (+164 mV), 5 samples`, and battery alert `OK`.
- The retained cloud state reported level `ok` and no alert history.
- A post-update Make API read returned the two persisted subject rules with the intended AND relationship.
- Cloudflare Worker v0.2.2 code and the panel bundle were deployed successfully before publication.
- Cloud monitor tests, panel tests, panel production build, and Wrangler dry-run passed locally.

The meter available for the current field check only resolves the battery to the `3.7-3.8 V` range. That observation supports the existing `3.76 V` calibrated result but is not precise enough to justify changing the `+164 mV` offset. This release therefore fixes data ownership and alert routing without inventing a finer calibration point.

## Security and Deployment Notes

- Live credentials, webhook URLs, OAuth tokens, calibration variables, and retained operational payloads are not included in source, packages, or Release assets.
- The Release firmware bundle remains an example build from public configuration and is not required for this remote correction.
- The monitor and panel MQTT accounts should remain limited to the mailbox topic prefix where broker ACLs support it.
- Real low/critical alerts still use hysteresis and a 24-hour repeat cooldown after cloud calibration.
