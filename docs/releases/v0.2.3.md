# LoRa Mailbox Gateway v0.2.3

Version 0.2.3 is the finished remote-only battery telemetry release. It includes the v0.2.2 topic-ownership and alert-routing correction, then localizes the complete production web experience into Simplified Chinese. The installed mailbox node does not need to be retrieved or reflashed.

## Highlights

- Presents the passkey login, live status, battery source, alerts, controls, confirmations, errors, maintenance state, and relative times in Simplified Chinese.
- Keeps GitHub documentation, package metadata, source comments, and Release Notes in English.
- Uses dedicated `mailbox/heartbeat-calibrated` and `mailbox/status-calibrated` topics for stable calibrated battery data.
- Keeps `mailbox/heartbeat` and `mailbox/status` gateway-owned, preventing raw and calibrated retained values from overwriting each other.
- Preserves the deployment calibration, five-sample median, 10 mV display step, and linear `3.3 V = 0%`, `4.2 V = 100%` mapping.
- Keeps uncalibrated legacy low/critical firmware email subjects suppressed while allowing delivery, invalid-telemetry, and calibrated battery alerts.
- Confirms that firmware low-battery classification only updates alert state and sends a webhook; it does not shut down or power off the installed node.

## Battery Correction

The installed firmware reports the divider/ADC result without the deployment-specific correction. The cloud monitor applies the measured `+164 mV` offset, filters the latest five distinct samples, and recomputes percentage. The Worker is now the sole writer of calibrated topics, while the gateway remains the sole writer of raw topics.

Before the ownership split, a gateway heartbeat could replace a calibrated retained value and the next Worker run would replace it again. That race caused the panel to alternate between contradictory readings. Dedicated topics remove the race without changing the installed firmware.

The field meter currently resolves the battery only to the `3.7-3.8 V` range. That supports the production panel's approximately `3.75 V / 50%` calibrated result but is not precise enough to justify changing the existing offset.

## Chinese Web Experience

The production site now uses `lang="zh-CN"` and Chinese user-facing text throughout:

- passkey login and optional first-device registration;
- connection, mailbox, gateway, heartbeat, battery, alert, mode, sampling, uptime, event, and maintenance states;
- cloud-calibrated versus raw-node battery-source labels;
- collection, heartbeat, debug, test-delivery, and maintenance controls;
- confirmation prompts and visible configuration or authentication errors.

Protocol values, MQTT topics, API routes, and stored payload fields remain unchanged, so localization does not affect gateway or Worker compatibility.
