# LoRa Mailbox Gateway v0.2.1

Version 0.2.1 is the published no-reflash battery telemetry release. It supersedes the signed but unpublished v0.2.0 candidate by aligning the cloud-monitor CI runtime with Wrangler's Node.js 22 requirement; no v0.2.0 GitHub Release or npm package was published.

## Highlights

- Added `cloud-battery-monitor/`, a scheduled Cloudflare Worker that reads retained MQTT heartbeat/status data over WSS and republishes calibrated values on the existing topics.
- Kept the embedded mailbox node and home gateway firmware untouched for this correction path.
- Added five-distinct-sample median filtering and 10 mV display rounding to suppress implausible minute-to-minute voltage movement.
- Replaced firmware-reported percentage in the cloud path with a documented linear calculation: 3.3 V is 0% and 4.2 V is 100%.
- Added calibrated low/critical alert evaluation with hysteresis and a 24-hour repeat cooldown.
- Preserved raw millivolts, raw percentage, calibration metadata, and filter sample count in retained payloads for auditability.
- Added a retained `mailbox/battery-cloud-state` topic, avoiding a separate KV/database dependency.
- Updated `@feierbuqiu/lora-mailbox-panel` to 0.2.1 and documented compatibility with calibrated retained telemetry.
- Updated SimpleWebAuthn from server/browser 11 to server 13.3.2 and browser 13.3.0, including the upstream certificate-chain verification fix.
- Updated official GitHub Actions to their current major releases and added independent panel/cloud-monitor tests.

## Root Cause and Resolution

The installed node reported roughly 4.05 V while a meter reading at the battery showed approximately 4.21-4.22 V. The firmware path could not be changed without physically retrieving and reflashing a permanently installed node.

The cloud monitor applies a deployment-specific millivolt offset before filtering and percentage calculation. The public source default is intentionally 0 mV; each deployment must set `BATTERY_OFFSET_MV` from its own meter comparison. This keeps the repository reusable without publishing one installation's ADC/divider correction as a universal constant.

The Worker ignores payloads marked with its calibration identifier, so republishing to the existing retained topics cannot create a feedback loop. It only adds a filter sample when the raw heartbeat timestamp changes.

## Validation

- Firmware: `home`, `mail`, and `hello` PlatformIO environments compile from the public example configuration.
- Panel: build, source-only package inspection, dependency audit, and SimpleWebAuthn registration-options smoke test pass.
- Cloud monitor: 10 unit tests and Wrangler production-bundle dry-run pass under Node.js 22.
- Live MQTT: successive raw readings were corrected and retained while the existing panel continued to display a stable calibrated voltage and percentage.
- HTTP: the Worker health endpoint returned 200; the protected manual-run endpoint returned 401 without its bearer token.
- Supply chain: the panel package contains six public source files only; live credentials, deployment output, and local state are excluded.

## Security and Deployment Notes

- Live MQTT credentials, webhook URLs, Cloudflare tokens, admin bearer tokens, calibration values, and retained operational captures are not included in source or Release assets.
- The monitor MQTT account should be limited to the mailbox topic prefix where broker ACLs support it.
- The Release firmware bundle is built from the public example configuration and is not a drop-in production image.
- Existing legacy low/critical firmware email subjects may be filtered in the automation layer to prevent duplicate or premature mail; delivery, invalid-telemetry, and sustained-offline alerts should remain enabled.
